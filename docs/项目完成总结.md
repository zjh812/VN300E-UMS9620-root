### 这个镜像做了什么（10 条 magic64 运行时补丁）

| code offset | 原指令 | 目标 | 作用 |
|---|---|---|---|
| `0x627E8` | `0xB948CA95` | `0x52800035` | 强制解锁（`read_lock_flag` 失败时的提前返回路径） |
| `0x627F0` | `0x97FF3759` | `0xB908CA95` | 同上：写 `g_DeviceStatus = 1` |
| `0x62830` | `0x350002A0` | `0xD503201F` | 强制解锁（读成功时的校验路径） |
| `0xB4B0` | `0x54000060` | `0xD503201F` | 去掉 `INFO: Press power button to pause.` + 10 秒倒计时 |
| `0xB504` | `0x54000180` | `0xD503201F` | 去掉 `INFO: LOCK FLAG IS : UNLOCK!!!` |
| `0xB7478` | `0x1D000A16` | `0x1D000016` | 跳表：state 1 → state 2（去掉「不同 OS」整组警告） |
| `0xB7B8` | `0x94009DA3` | `0xD503201F` | 去掉 `WARNNING: … SKIP VERIFY!!!`（UART） |
| `0xB7C0` | `0x9401F0BD` | `0xD503201F` | 同上（屏幕） |
| `0x6AC10` | `0xB4000060` | `0xD503201F` | 降级加载器补丁（让改过的 init_boot 能加载） |
| `0x6AC18` | `0xB5FFF820` | `0x17FFFFC1` | 同上 |

**LOAD_BASE = `0xB5000000`**（由设备自身 `uboot_log` 实证推导）

## 关键结论（这版固件的事实）

1. **DHTB 结构**：header `0x200`，payload `0x200..0x171830`（`data_size=0x171630`），
   **DHTB hash == SHA256(payload)**；SIMGHDR @`0x171830`（`0x60` 字节），
   证书块 = `sig_struct_size` = `0x458`；`code_off = file_off - 0x200`
2. **SPL 认 magic64 布局**：`sechdr = image + 0x200 + data_size`、
   `payload = image + sechdr[+0x18]`、payload 长度取 `sechdr[+0x10]`、
   `cert = image + sechdr[+0x28]`（绝对偏移）—— 全部代码级验证通过
3. **magic64 在这台机器上可用**（`MAGIC6 PROBE OK` / `MGC6ome` 标记实证）
4. **锁定态下 `/data` 与「跳过校验」不可兼得** —— 解锁态（orange）会触发一次清数据
5. **本机 `miscdata[0x2000]` 是全 0** → `read_lock_flag()` 返回 -1 →
   `get_lock_status()` 提前返回 0 → 所以最初的 patch ① 空转（这是整个过程中最大的坑）

## 刷写命令（以后要改 uboot 时用）

### 方式 A：BROM（稳，推荐）
```bat
cd /d C:\Users\admin\Desktop\B\T9100\unlock_ums9620\dramtype2
spd_dump --wait 300 exec_addr 0x65012f48 fdl fdl1-dl.bin 0x65000800 ^
         fdl fdl2-dl.bin 0xb4fffe00 exec w uboot_b <镜像> reset
```
（关机 → 按住 电源+音量上 不松手插 USB → 进 BROM）

### 方式 B：系统内 dd（快，需 root 授权）
```bat
adb push <镜像> /data/local/tmp/u.img
adb shell /data/adb/ksu/bin/su -c "dd if=/data/local/tmp/u.img of=/dev/block/by-name/uboot_b bs=4096"
adb shell /data/adb/ksu/bin/su -c "sync"
adb reboot
```
